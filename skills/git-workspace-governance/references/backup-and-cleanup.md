# 备份与清理授权

决定“清理前备份什么、删什么、谁能授权”时读取。核心原则：**先备份后删除；只备份不可再生的最小集合；备份本身不授权清理。**

## 1. 先分类，再决定备份

| 内容 | 是否备份 | 理由 |
|---|---|---|
| 已提交且已推送到远程的源码 / 历史 | 否 | 远程仓库已有；本地 clone 可重建 |
| 依赖、虚拟环境、`node_modules`、浏览器缓存、构建产物 | 否 | 可重建；体积大但不是资产 |
| 本地独有提交、分支、stash | 是 | 远程可能没有 |
| staged / unstaged 改动（含二进制） | 是 | 未提交即未纳管 |
| 任何 ref 都没有的 untracked 文件 | 是 | 只在工作区存在 |
| 私密配置、凭据（保持最小） | 是 | 不能提交、不能外传，权限收紧 |
| 运行数据库 / ignored 数据目录 | 先评估 | 可能有独有数据；确认前不删也不假设可弃 |
| 任务证据、交接文档、知识产物 | 视价值 | 小体积、不可再生的建议保留 |

“已提交”以远程 ref 为准，不以本地分支存在为准。

## 2. 最小备份的几种载体

- **Git bundle**：保存本地独有 refs/历史。`git bundle create <file> --all`（或指定 refs）；
- **补丁**：`git diff --staged`、`git diff`、`git diff --binary`，以及未跟踪文件清单；
- **打包**：只打包确认不可再生的路径，显式列清单，避免整目录快照；
- **私密配置**：单独小包，目录 0700、文件 0600，不进入 Git 或公开归档分支。

命名建议：`<repo>-<purpose>-<UTC timestamp>`，并附 `SHA256SUMS` 和覆盖范围说明。

## 3. 目录状态说明模板

每份备份记录以下字段：

```text
scope:           备份了哪些树 / 路径 / refs
exclusions:      明确没备份什么（依赖、缓存、大数据等）及原因
volatile:        打包期间可能仍在变化的内容
validation:      恢复验证方式与结果
retention:       本地保留期限与到期处理
authority:       这份备份不构成任何清理授权
```

## 4. 验证

- bundle：`git bundle verify <file>`，并在临时目录 `git clone` 读回所需提交；
- 补丁：在临时 worktree 上 `git apply --check`；
- 打包：列出归档内容并抽查校验和；
- 备份校验通过之前，不删除任何源内容。

## 5. 清理授权流程

1. 生成**候选清单**：路径 / 分支 / worktree、当前状态、判定依据；
2. 核对归属：任务 owner、PR/合入状态、运行消费者、ignored 资产；
3. 向用户展示候选清单，取得**明确到路径范围**的授权；
4. 逐项执行普通（非 force）Git 操作；
5. 报告实际删除/保留了什么，以及仍待确认的项。

“干净”“已合入”“PR 已关闭”只是候选信号，都不是删除授权。

## 6. 禁止操作

| 禁止 | 原因 |
|---|---|
| `git clean -fd/-fdx` | 会删除 Git 不知道的本地文件，包括唯一副本和私密配置 |
| `git reset --hard` / `git checkout --` | 覆盖未提交内容，且不可恢复 |
| `git worktree remove --force` | 绕过未提交内容检查 |
| 批量 `prune` / 自动删分支 | 把“看起来没用”当成“确认无用” |
| 整目录快照当作备份 | 体积大、含敏感内容、掩盖真正不可再生的部分 |

## 7. 灾备边界

同一块磁盘上的备份只能防误清理，不是异机灾备。若需要灾备，把最小集合（bundle、补丁、校验清单）推送到远程私有位置或另一台机器，并验证可读回。

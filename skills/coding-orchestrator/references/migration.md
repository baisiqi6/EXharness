# 合并旧路由与迁移安装

本编排器集中维护方法选择、抽象取舍和实际冲突处理。旧的二级路由完成引用迁移后可退役；通用编码指南、设计模式及其它专项能力继续独立保留。

## 可选集成（非依赖）

| 能力 | 旧示例（如存在） | 不再使用旧入口时 |
| --- | --- | --- |
| 在编码纪律与结构方法之间路由 | `programming-principles` | 由本编排器按任务直接选择专项能力，不再串联一次路由。 |

## 顺序

1. 只读核对各客户端实际发现的旧入口、来源/安装归属、本地修改，以及项目指令、接入记录或其它调用方的引用。分清库副本、部署副本和符号链接。
2. 按原安装方式安装选定的固定版本候选；在隔离测试中确认它可独立工作，原专项能力仍可按需使用。仓库有文件不代表客户端已加载。
3. 在各自授权范围更新引用，保留项目规范和任务 locator。若同名新旧入口同时存在，先按客户端实际发现规则处理冲突，不能依赖未核验的路径优先级。
4. 读回实际加载来源，并确认原引用已经迁移，再按安装归属和已有授权退役旧路由。托管内容走所属管理器；手动安装先保留本地独有修改，不批量删除其它 skill。
5. 核对新会话发现结果及原任务接续。合并、发布、更新安装和旧入口退役分别报告；未完成的阶段保持明确。

此说明不执行安装、删除或修改全局配置。迁移尚未完成时继续保留可工作的旧入口，避免先移除后补接。

# 规范接入记录

第三方与个人规范使用相同的 Markdown 记录。复用项目现有规范索引、配置或任务引用；已有足够信息时直接引用，不另建注册库。
记录可留在用户选择的私有位置。新增一种规范不需要改编排器内核，也不自动触发安装、更新或全局配置变更。

## 最小模板

```markdown
# <规范名称>

- 来源与固定版本：<官方来源 URL + commit/tag，或个人文档 locator + 修订标识>
- 适用与不适用：<哪些任务/阶段需要它，何时直接继续现有流程>
- 选用依据：<用户要求或项目约定；尚未选用时注明仅为候选>
- 实际入口：<当前客户端已安装 skill、命令或本地文档入口；未安装则注明>
- 原生产物与项目引用：<规范/设计/执行计划各自的正式位置与现有 locator>
- 已知冲突与处理：<实际矛盾、采用依据、尚需谁决定；未发现不等于已全面兼容>
- 验证范围：<实际版本、客户端、任务、结果和证据 locator；未验证项明确列出>
```

## 使用与更新

选中规范后先核对实际入口与版本，只读当前步骤需要的内容。多个同名版本用来源和版本区分，不依赖客户端的同名发现顺序。
规范提供钩子、工具或多阶段命令时，保留其真实运行前提；接入记录只说明如何使用，不替代工具本身。
更新版本或改变项目选用方式时，先核对入口、原生产物和已知冲突的变化，再运行受影响的具体任务；保留未经验证的边界。

例如，个人规范只要求“此项目的新公共行为先补测试”，可在项目已有规范中声明其范围和修订，再引用现有测试命令与计划位置。
使用该要求不意味着需要引入完整规格框架；验证结果仍以实际测试为准。

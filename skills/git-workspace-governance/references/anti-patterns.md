# 常见自欺与红旗

这些说法出现时，停下来回到只读核对。表里的左列是真实发生过的合理化，右列是事实。

| 想法 / 说法 | 事实 |
|---|---|
| “目录叫 main，肯定就是主线” | 目录名不进入 Git 事实；看 `git rev-parse HEAD` 和当前分支 |
| “本地 main 就是远程 main” | 本地分支只是缓存；远程可能已前进，二者是不同的 SHA |
| “工作树干净，可以删了” | 干净只覆盖 tracked/untracked；ignored 资产、运行消费者、合入证据都还没核对 |
| “依赖反正能重新拉，先整包备份” | 依赖可重建，不属于备份对象；整包快照掩盖真正不可再生的内容 |
| “clean 一下最快” | `clean` 删除 Git 不知道的本地文件，包括唯一副本和私密配置 |
| “这个分支合入了就能删” | 合入只是候选信号；owner、运行依赖、本地独有提交仍需核对 |
| “HEAD 不在主线历史，说明没合入” | 可能已 squash 合入；要查 PR/合入证据，不能只看祖先关系 |
| “合入 main 就算发布” | 合并、部署、业务验收是三件事 |
| “只有我在这台机器上，不会冲突” | 其它 session、agent、后台任务都可能在同一棵树上写 |
| “先切过去看看，有问题再切回来” | 切分支会改变共享树；未备份的未提交内容可能直接丢失 |
| “我在主 checkout 上开个分支就行” | 任务应使用独立 worktree；主 checkout 保持集成分支 |
| “temp 目录放任务树没关系” | 系统临时区会被清理；长期任务树应放项目约定位置 |
| “我 clean/stash 的是自己的改动” | 树可能是共享的；清理前先确认归属，不做跨树操作 |
| “先把其它人的改动 stash 掉再继续” | 不被授权覆盖他人未提交内容；应换独立 worktree 或协调 |
| “AGENTS.md 顺手改一下，反正是为了提醒自己” | 项目准则文件属于人类；先建议、给草案、取得授权后再走 PR |
| “把整份 skill 规范贴进 AGENTS.md 最保险” | 会重复、漂移、挤占上下文；只放入口和关键边界 |
| “项目没有 AGENTS.md，我建一个” | 先建议用户决定位置与内容，不擅自往仓库加 instructions 文件 |

## 红旗清单

出现以下任一情况，停止并先做只读核对：

- 准备执行 `clean`、`reset --hard`、`checkout --`、`worktree remove --force`、批量 `prune`
- 准备在 primary checkout 上开发或提交
- 线上/共享树上出现不是自己创建的改动
- 准备删除已合入分支或 worktree，但没有 owner 确认
- 准备发布，但四个 SHA 没有分别读回
- 用“应该”“我记得”“大概是”描述仓库状态

## 正确姿势（一句话版）

先只读体检 → 明确位置与归属 → 在独立 worktree 写 → 审查合入 → 发布前读回四个 SHA → 备份后才谈清理。
